= The Host View

Open http://hostinfo-{guid}.{domain}[*the hostinfo application*^] and enable the Host View using the toggle.

image::host_view_toggle.png[Host View toggle control]

The warning banner lists the resources the application needs but cannot see — they exist on the host but have not been made available inside the container. Each step in this module provides one of those resources and clears part of the warning.

image::initial_host_details_errors.png[Host view with warning banner and missing resource indicators]

== Host Hostname

The container view shows the autogenerated container hostname. The host view is designed to show the actual host hostname, but the application has no way to discover it across the isolation boundary — it must be provided explicitly as an environment variable.

[source,bash,role=execute]
----
podman run --replace -d -p 8000:8000 --name hostinfo \
  -v ~/hostinfo-config/config.json:/app/config.json:ro,z \
  -e HOST_HOSTNAME=$(hostname) \
  ${REGISTRY}/hostinfo-app
----

Open http://hostinfo-{guid}.{domain}[*the hostinfo application*^] and check the host view. The hostname now appears and the error indicator for the missing variable clears.

image::hostname_updated.png[Host view showing hostname populated after HOST_HOSTNAME injection]

== Host Operating System

The application needs `/usr/lib/os-release` to display host OS information. Mount it read-only:

[source,bash,role=execute]
----
podman run --replace -d -p 8000:8000 --name hostinfo \
  -v ~/hostinfo-config/config.json:/app/config.json:ro,z \
  -e HOST_HOSTNAME=$(hostname) \
  -v /usr/lib/os-release:/host/os-release:ro \
  ${REGISTRY}/hostinfo-app
----

No `:z` here. `os-release` is a host system file — it belongs to the host, not to this container's configuration. Relabeling it would change its SELinux context on the host for every process that reads it. System files being borrowed read-only get `:ro` only.

Open http://hostinfo-{guid}.{domain}[*the hostinfo application*^] — the host OS distribution appears and the corresponding warning clears. The package table now shows the host context but cannot yet resolve versions without the RPM database.

image::release_info_updated.png[Host view showing RHEL distribution after os-release mount]

image::host_rpmdb_missing.png[Package table showing host context but packages not yet found]

== Host Package Information

The application needs `/var/lib/rpm` to query the host's package database:

[source,bash,role=execute]
----
podman run --replace -d -p 8000:8000 --name hostinfo \
  -v ~/hostinfo-config/config.json:/app/config.json:ro,z \
  -e HOST_HOSTNAME=$(hostname) \
  -v /usr/lib/os-release:/host/os-release:ro \
  -v /var/lib/rpm:/host/var/lib/rpm:ro \
  ${REGISTRY}/hostinfo-app
----

Open http://hostinfo-{guid}.{domain}[*the hostinfo application*^] — the host package list populates and the warning banner clears.

image::host_rpmdb_updated.png[Package table showing host packages resolved from the RPM database]

== Container View and Host View

The two tabs show two separate views through the same application. The container view reflects the image and its baked-in configuration. The host view shows only what you chose to make available — the hostname, OS, and packages the container was given explicit access to.

Each mount and environment variable was a deliberate decision. The container cannot reach anything else on the host filesystem. The boundary is defined by exactly what you provided.
