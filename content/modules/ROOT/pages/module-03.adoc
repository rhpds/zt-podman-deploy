= Configuring the Application

Open http://hostinfo-{guid}.{domain}[*the hostinfo application*^] and look at the container view. The application knows it is running in a container, reports the distribution from the image, and shows the autogenerated container hostname. The package lists are the defaults baked into the image — the same on every new container. The goal of this module is to replace that configuration from the host without modifying or rebuilding the image.

image::container_details.png[Container view showing default OS information and autogenerated hostname]

image::orig_system_pkgs.png[Container view showing default system package list from the image]

== Create a Custom Configuration

[source,bash,role=execute]
----
mkdir -p ~/hostinfo-config
----

[source,bash,role=execute]
----
cat > ~/hostinfo-config/config.json << 'EOF'
{
  "python_packages": ["flask", "gunicorn"],
  "system_packages": ["glibc"]
}
EOF
----

== Inject Configuration with a Volume Mount

Files in your home directory carry the SELinux label `user_home_t`. Container processes are not permitted to read that label by default — mounting the file without addressing this will produce a permission denied error even though the path is correct.

Remove the existing container and start a new one with the file mounted:

[source,bash,role=execute]
----
podman rm -f hostinfo
----

`podman rm -f` force-stops and removes the container in one step. Use it when you need a clean restart and the running state doesn't need to be preserved gracefully. You'll see a better approach for iterative changes in a moment.

[source,bash,role=execute]
----
podman run -d -p 8000:8000 --name hostinfo \
  -v ~/hostinfo-config/config.json:/app/config.json:ro \
  ${REGISTRY}/hostinfo-app
----

The container starts, but cannot read the file. Confirm what it sees:

[source,bash,role=execute]
----
podman exec hostinfo cat /app/config.json
----

[source,text]
----
Permission denied
----

== SELinux Context

Check the label on the file:

[source,bash,role=execute]
----
ls -Z ~/hostinfo-config/config.json
----

[source,text]
----
unconfined_u:object_r:user_home_t:s0 /home/rhel/hostinfo-config/config.json
----

Diagnosing a permission denied error like this normally involves checking the audit log — `ausearch -m avc -ts recent` would show a SELinux denial. In this case we already know the cause: the `user_home_t` label on the file. The `:z` volume option relabels the file to `container_file_t`, a type container processes are permitted to read.

This relabeling is appropriate for `config.json` because it exists solely to support this container — it belongs to the container's configuration. The question is not where the file lives but who owns it: files created for the container's use can be relabeled; host system files being borrowed should not be. You'll see that distinction applied in the next module.

[source,bash,role=execute]
----
podman run --replace -d -p 8000:8000 --name hostinfo \
  -v ~/hostinfo-config/config.json:/app/config.json:ro,z \
  ${REGISTRY}/hostinfo-app
----

`--replace` stops and removes the existing container atomically before starting the new one. For iterative changes this is cleaner than `rm -f` followed by `run` — the transition is a single operation rather than two. Note that `--replace` creates a new container, so logs start fresh from that point.

== Verify the Change

Check the logs to confirm the new container started and loaded:

[source,bash,role=execute]
----
podman logs hostinfo
----

[source,text]
----
[2026-08-17 19:31:04 +0000] [1] [INFO] Starting gunicorn 21.2.0
[2026-08-17 19:31:04 +0000] [1] [INFO] Listening at: http://0.0.0.0:8000 (1)
[2026-08-17 19:31:04 +0000] [1] [INFO] Worker booted
[2026-08-17 19:31:04 +0000] [7] [INFO] Booted worker with pid: 7
----

Open http://hostinfo-{guid}.{domain}[*the hostinfo application*^] — the package list in the container view reflects the custom configuration.

image::custom_config_system_pkgs.png[Container view showing custom package list with only glibc]

[source,bash,role=execute]
----
ls -Z ~/hostinfo-config/config.json
----

[source,text]
----
system_u:object_r:container_file_t:s0 /home/rhel/hostinfo-config/config.json
----

The label is now `container_file_t`. The file was relabeled when the volume was mounted with `:z`.
