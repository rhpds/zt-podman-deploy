= Observing the Application

These tools let you see what a running container is doing without disrupting it. Containers include only what the application needs — common diagnostic tools like `ps` may not be present inside. Podman provides equivalents from outside the container boundary.

== Start the Application

[source,bash,role=execute]
----
podman run -d -p 8000:8000 --name hostinfo ${REGISTRY}/hostinfo-app
----

== Execute Commands in a Running Container

`podman exec` runs a command inside an already-running container. The container keeps running — you are not starting a new one.

Read the application's current configuration:

[source,bash,role=execute]
----
podman exec hostinfo cat /app/config.json
----

[source,text]
----
{
  "python_packages": ["flask", "gunicorn", "requests", "psutil"],
  "system_packages": ["glibc", "openssl", "python3"]
}
----

The two lists control what the application displays in its web UI. This configuration is baked into the image — every new container starts with it.

Get an interactive shell to explore the runtime environment:

[source,bash,role=execute]
----
podman exec -it hostinfo /bin/bash
----

Check what environment variables the container started with:

[source,bash,role=execute]
----
env
----

Check the actual process command being run:

[source,bash,role=execute]
----
cat /proc/1/cmdline | tr '\0' ' '
----

[source,text]
----
/app/venv/bin/python /app/venv/bin/gunicorn --bind 0.0.0.0:8000 app:app
----

Now try to list running processes:

[source,bash,role=execute]
----
ps aux
----

[source,text]
----
bash: ps: command not found
----

`ps` is not in this image. Exit the shell:

[source,bash,role=execute]
----
exit
----

== Process View

`podman top` shows the processes inside the container from outside — no `ps` required:

[source,bash,role=execute]
----
podman top hostinfo
----

[source,text]
----
USER        PID   PPID  %CPU  ELAPSED   TTY   TIME  COMMAND
root        1     0     0.00  3m21s     ?     0s    /app/venv/bin/python /app/venv/bin/gunicorn --bind 0.0.0.0:8000 app:app
root        7     1     0.00  3m21s     ?     0s    /app/venv/bin/python /app/venv/bin/gunicorn --bind 0.0.0.0:8000 app:app
----

The gunicorn manager and worker process — the same view `ps` would give from inside, without needing `ps` to be installed.

== Resource Usage

[source,bash,role=execute]
----
podman stats hostinfo --no-stream
----

[source,text]
----
ID            NAME      CPU %   MEM USAGE / LIMIT   MEM %   NET IO        BLOCK IO  PIDS
a1b2c3d4e5f6  hostinfo  0.12%   45.3MB / 3.8GB      1.19%   1.2kB / 890B  0B / 0B   3
----

A point-in-time snapshot of CPU, memory, network I/O, and block I/O. `--no-stream` prints once and exits; omit it to follow continuously.

== Container Configuration

`podman inspect` shows the full container configuration. Scope it to what's relevant rather than reading the full output:

[source,bash,role=execute]
----
podman inspect hostinfo --format '{{.Config.Env}}'
----

[source,text]
----
[PATH=/app/venv/bin:/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin]
----

The environment the container started with — only what the image defined. No custom variables have been injected yet.

[source,bash,role=execute]
----
podman inspect hostinfo --format '{{.Config.Image}}'
----

[source,text]
----
registry-xxx.example.com/hostinfo-app:latest
----

[source,bash,role=execute]
----
podman ps
----

The container is still running. None of these tools affected its lifecycle.
